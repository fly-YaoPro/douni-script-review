# 课程教学审稿

课程教学是系列教程，不是把一条普通种草脚本拉长。

真实样本的完整归纳见 `course-teaching-review-patterns-2026-09.md`。审核时先按本页还原整篇，再检索相似真人案例；不得从历史评论反推固定模板。

## 系列逻辑

- 系列应有清楚的大主题和递进关系，每期解决一个小问题，技能或使用深度逐步升级。
- 不要一个 Skill 换皮讲多期；也不要三期完全无关联。
- 方向一：0 到 1 教会用户创建、克隆或使用内置 Skill。
- 方向二：双端互通 + 云电脑等组合能力，适合小体量达人/KOC。
- 单期可按教程需要组合 2–3 个 Skills，但要有主次；不能堆叠成报菜名。

## 单期脚本

- 开头先给本期能学会什么、解决什么问题和最后成品。
- 课程教学的主体是 Skill，而不是案例本身。无论脚本采用体验、口播或案例演示，观众最终应掌握三层内容：
  1. **Skill 的功能**：用普通用户能懂的话讲清适用场景、能完成什么、主要产物或可观察效果；不能只念官方简介。
  2. **Skill 的使用思路**：借当前用例解释如何顺着 Skill 的能力准备输入、组织提示词、作出关键选择、检查和优化结果；篇幅允许时再补进阶用法或可迁移场景。重点是让观众下次能自己用，不是逐字抄本次 Prompt。
  3. **Skill 的好处**：结合产物说明它实际省了哪一步时间、降低了什么专业门槛，或怎样通过固定流程/结构提高稳定性。没有依据时不要硬说“稳定不抽卡”。
- 以上三层是内容判断维度，不是固定段落模板。可以穿插讲，也不要求每个维度等长；但用例只能作为说明和证据，不能占满正文后只剩“我输入了什么、它生成了什么”。
- 每个主讲 Skill 的认知顺序必须成立：先让观众知道它是什么、适合什么场景、能完成什么、主要产出什么，再顺着当前用例讲怎么用、怎样优化和实际效果。视频开头可以先用痛点或结果抓人，段内也不要求背定义；这里的“先”是先建立足够的通用认知，不能让观众直到案例讲完仍只知道这一次做了什么。
- 通用能力最好用 1–3 个跨场景例子帮助理解，但例子是解释能力边界，不是要求达人把所有例子都实际演示。是否补例子要看当前表述是否已经让普通人理解并能迁移。
- 审核一个 Skill 时，要看它从首次引入、操作演示到结果总结的整个教学段落，判断三层内容是否合起来成立，不能只盯着其中一镜或一句口播。某句话适合作为批注锚点，不代表全部修改都要塞进这句话；功能、方法和好处可以分布在整段口播、操作和产物展示中。
- 一条很长的案例 Prompt、按钮步骤和最终结果只能证明“演示过”。如果没有解释提示词为什么这样写、怎样根据结果继续调整、换一个对象时怎样复用，使用思路只能判为部分覆盖；如果没有明确说产物替用户省掉哪一步、降低什么门槛或为什么更稳定，好处也只能判为部分覆盖。
- 步骤必须能跟做：输入、操作位置、关键选择、产出和修正都要明确。提示词不只展示结果，还要说明至少一个真正影响产物质量的写法或选择。
- 展示真实操作与实际产物，必要时补失败或修改过程，不能只讲“它很方便”。
- 与前后期关系明确，但本期单独看也能完成任务。
- 默认约 700–800 字、1.5–2 分钟；口播自然，术语用普通人能理解的话解释。
- 手机可以远程控制实体电脑、继续输入 Prompt 和推进电脑端任务，不只是查看进度或结果。当前阶段是否必须出现、是否必须前置，以审稿 Shard 和当期 Brief 为准。
- 云电脑可与双端并列或组合，但不是手机远控电脑的前提。只有脚本实际讲云端运行、本机不占用或设备关闭后继续时，才按云电脑能力核对。
- 课程教学允许为了讲清 Skill 而使用多个行业或场景，不套用工作任务“一条视频只能一个场景”的规则。

## 真实审稿样本得到的判断顺序

1. 先确认这期给谁看、承诺教会什么、最终产物是什么。
2. 把 Skill 分成 `primary`、`supporting`、`mentioned`，只对主讲 Skill 要求完整教学深度。
3. 对每个主讲 Skill 跨段落检查功能、使用思路和好处，不在单句上机械打勾。
4. 区分“提到、演示、教会”：按钮、长 Prompt 和结果展示只能证明演示；教会必须包含至少一个影响结果的真实判断或调整方法。
5. 删除案例中的具体对象后，如果观众几乎没有可复用方法，判定为案例吞掉教程；把整体意见锚定在“大纲”“脚本”等前部标题，再在最多两个位置补方法锚点，不创建文末全文评论。
6. 多 Skill 稿优先收窄主线。三个以上能力都讲得很浅时，不靠继续补字数解决。
7. 开头不机械套痛点：系列位置、本期玩法、适用人群和产物可择其关键项快速交代。
8. 给每个主要段落分配职责并检查节奏：功能解释负责建立认知，案例负责演示，结果负责证明，结尾负责收束。已经完成收束后又用同一观点再讲一遍，或铺垫过长挤掉 Skill 教学，应合并或压缩。

## 重点拦截

- 课程名义下仍是泛种草，没有可复现步骤。
- 全文聚焦某个用例的执行过程和结果，观众看完仍不知道 Skill 的通用能力、使用方法和实际价值。
- 把整段缺失误写成单句修改，导致达人只在某一镜补一句，其他案例流程仍然没有变成教程。
- 只展示一条很长的 Prompt，却不解释提示词为什么这样组织、哪些输入或约束决定结果质量。
- 只罗列产物中的数字、栏目或结论，没有把产物效果落到省时、降门槛或稳定性中的真实收益。
- 每期只是换输入，教学能力没有进阶。
- 同一期叠太多人群与场景，观众无法跟做。
- 使用明确旧产品全称“豆包专业版”或“豆包任务模式”作为对外名称。单独出现“工作任务模式”时先结合界面与上下文判断，不机械判错。

## 豆包 Skill 全量手册

- `doubao-skill-handbook.md` 是 108 个豆包内置 Skill 的二级能力参考，配套索引为 `doubao-skill-handbook-index.json`。
- 它用于发现某个 Skill 的适用场景、输入、产物、边界和可扩展玩法，帮助判断达人是否把能力讲错、讲窄或只讲了单次用例。
- 现行官方 `SKILL.md` 和实时产品资料优先级更高。手册与官方 Skill 冲突时以官方 Skill 为准。
- 只凭手册不能生成 `feature_error`。未找到官方佐证时，记录为内部待核实或可优化，不打扰达人。
