# 团队安装与每次更新

维护仓库：https://github.com/fly-YaoPro/douni-script-review ，默认分支 `main`。仓库已公开，包含原有 Brief、会议与审稿参考样本。下载不需要私有仓库授权；访问飞书源文档仍需要使用者自己的权限，不共享任何人的登录凭据。

## 同事首次安装

需要 Git、Python 3.10+、lark-cli。公开仓库可以匿名读取；如使用 Git 认证，交给本机凭据管理器，不要把 token 拼进 URL。先用 AI 客户端的 Skill 安装方式安装该仓库，或 `git clone https://github.com/fly-YaoPro/douni-script-review.git <客户端Skills目录>/douni-script-review`。ZIP 下载方式也支持：解压后让 `SKILL.md` 直接位于 `douni-script-review` 目录下，不能再套一层仓库名称。

让助手执行 `python "<Skill路径>/scripts/ensure_latest.py"`，成功后重新加载 Skill。Windows 使用 PowerShell 7；macOS/Linux 可将 `python` 换为 `python3`。无需安装内置 Workplace Skills 的依赖：它们仅用于核对能力，不在审稿时执行。

首次使用 lark-cli 时按其安装说明配置 CLI 应用，再用本人飞书账号授权。每人使用自己的登录态；已有有效认证不需要每次扫码。直接发稿件链接并说“审稿”，助手会说明当前登录人的姓名，然后以该身份读稿、评论及回读。

## 更新如何工作

每个审稿请求都运行检查脚本；同一批稿件固定使用检查时取得的同一个 GitHub commit，批内不升级。脚本只从上述仓库 `main` 拉取，通过 Git 获取并校验完整文件快照，以逐文件 SHA-256 核验本地安装，不能只比较文件名、版本字符串或修改日期。

- `latest`：已实时核验，文件一致，可以执行。
- `updated`：已备份变化文件并更新，必须重新加载入口和本次所需知识。
- `ok: false` / 非零退出码：网络、权限、文件写入或其他错误，未取得可执行的新版本；报告问题并暂停正式审稿。不能拿离线缓存冒充已核验。

`.local/` 保存本机更新状态、Git 缓存和锁；不随仓库上传，不放共享凭据。更新前的文件保存在安装目录同级的隐藏备份目录中。仅删除上一次版本明确管理且新版本已移除的文件；首次更新会将 `references/` 中的旧资料一起备份并清退，以免旧规则残留。额外个人文件请放 `.local/`，不要放入发布资料目录。失败自动恢复本次变化文件；异常终止遗留 `transaction.json` 时必须按其备份恢复后再运行，不能强行继续审稿。

脚本不运行下载资料里的命令、不更新 Git 远程配置、不推送个人更改。若安装目录本身是 Git 克隆，脚本更新文件但不改它的 HEAD/index；维护者应在独立发布工作目录提交发布，别从自动更新的安装目录直接推送。

GitHub 最新版表示“最新已发布的规则包”，不代表每份源 Brief 都刚同步。源资料仍保留原始同步日期；明确的本次客户新口径按规则优先级处理，不能用版本检查掩盖资料时效性。
