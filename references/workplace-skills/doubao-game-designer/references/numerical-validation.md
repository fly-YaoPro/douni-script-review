# 数值校验与依赖复算

本文件用于经验、概率、DPS、EHP、TTK、时间、价格、资源循环、成长可达性、容量或其他多步公式。第一份数值产物来自计算器、表格、代码或契约校验器；正文复制经过复算的结果。检查范围同时覆盖公式权限、输入来源、单位、完整依赖和正文版本。

## 1. 计算前锁定输入

先把本轮必须证明的数值问题写成可证伪命题，明确比较对象、场景或时间窗、决定性指标和通过条件，再记录输入、单位、来源、合法上下限、取整方式、生效时点和依赖关系，并写入设计契约的 `numeric_requirements`。若断言失败仍不改变设计结论，它只是辅助指标。不能用两个无关算例代替真正要求的 EHP×DPS、升级次数、回报、节奏或容量验证。

先画最短推导链，再开始代数。最终状态由掉落、抽取或多部位收集形成时，链路至少经过：

`资源/时间 → 可执行次数 → 产出机会 → 品质或候选分布 → 重复与槽位覆盖 → 玩家最终状态`

“平均品质”“平均收益”不能替代全套毕业概率、最低路径或部位补齐问题。阶段成长同时检查终点和中间节奏：终点达标但连续多个阶段没有可感知变化，也属于设计未成立。

公式本身同样具有来源。用户明确给出减法、乘法、结算顺序或预算口径时沿用该公式；需要改变公式时先作为设计范围变化裁决。

未知的当前配置、真实产能、统计口径和实体是否存在不能用设计初值代替。`current_config` 和外部参数必须回指已经读取的文件或 URL；测试初值必须明确标注为未经验证。

## 2. 使用工具复算

累计经验、升级次数、概率、DPS、EHP、TTK、时间、价格、收益、资源循环或多步公式调用计算器、表格或代码工具。

多步公式用可执行表达式或表格复算，再把决定性结果写入设计契约的 `numerical_assertions`。每项决定性断言包含场景、表达式、输入、结果、单位、容差与通过条件。

校验器重新计算 `expression`，不能把 `declared_value` 当作正确答案。表达式可使用加减乘除、整数幂以及 `floor`、`ceil`、`abs`、`min`、`max`、`clamp`；更复杂的序列、分布和模拟由代码或表格完成，再把关键输入、结果与通过条件回填契约。

## 3. 场景覆盖

每个数值系统至少验证：

- `normal`：标准路径；
- `boundary`：0、上限、最低收益、提前消费、最后可用时点或最大叠加；
- `abuse`：仅在递归、叠加、刷取、无限等待或支配策略真实存在时加入。

概率检查总和、移除、保底、饱和、重复和取整；DPS/EHP/TTK 检查攻速、目标数、覆盖时间、伤害口径和正确/错误配置差；资源检查逐时点余额、最低收入路径、可购买次数与期末值；容量检查任务总量、依赖、联调、验证和时间预算。计算结果同时回答它绑定的数值问题，局部算式通过不代表任务通过。指标由当前游戏规则决定：职业等强可以比较同一基线下的综合战斗贡献，成长节奏可以比较玩家输出、敌方有效生命与阶段 TTK 的相对曲线；控制、射程、AOE、机动或团队价值存在时单独建模，不把示例公式当成通用答案。

复算后做一次量纲与语义核对：

- `x 倍`、`提升 y%` 与 `增加 y 个百分点` 分开表达；
- 池、牌组、手牌、候选和最终选择保持不同对象；
- 总产出与某时点前已获得产出分开；
- 候选分布、实际选择分布与最终持有分布分开。

边界例使用当前规则能够到达的等级、层数、资源和对象数。需要验证程序钳制时，可以另设调试输入，但要与玩家可达结论分开。比较构筑或方案时固定升级次数、目标、时间窗和命中条件；群体收益写明有效目标数，控制与生存价值单列，不用不同基线支撑强弱结论。

## 4. 参数修改后的下游复算

发现问题时先辨认权威层级：

`用户与当前项目事实 → 公式 → 设计参数 → 派生结果 → 示例和测试 → Demo → 叙述`

上游正确时修改下游；设计关系不成立时，只调整拥有权限的最小杠杆。缺少真实数据时给确定的设计初值、合法范围和校准规则，不把假设改写成现状。

修改任一参数或公式后：

1. 找出全部引用它的公式、账本、测试、示例和正文表格。
2. 用工具重新计算并替换旧结果。
3. 检查总量、次数、容量、时间预算、阶段余额和可达性。
4. 使用统一契约时重新运行校验。
5. 回读正文、配置、测试和 Demo，确认没有引用旧版本。
6. 让独立审查者只复核本次影响面，并从原始需求做一次全局覆盖检查。

只验证局部算式，不能证明完整依赖关系成立。

## 5. 资源与数值账本

资源账本至少包含主体、单位、起始量、每笔收入和支出、发生顺序、逐时点余额、期末值及可达次数。多人资源、团队资源和个人资源分别建账，不能混算。

正文中出现“剩余”“最多”“至少”“无法购买”“刚好用完”等结论时，必须有对应数值断言。概率、经验、时间轴和人日采用同样原则。

## 6. 结论边界

算式正确只证明所用输入和公式在当前版本成立，不证明：

- 输入来自真实现网配置；
- 玩家会按标准路径行动；
- 数值已经平衡；
- 小样本结论可以外推。

体验与平衡结论仍需真人试玩或线上数据验证。
