# 策划评审与修订

## 1. 先确定评审对象

先说明本次评审要判断什么：概念方向、核心循环、单个机制、数值关系、内容结构、制作范围，还是文档可用性。不要用完整 GDD 标准处罚一份明确的早期概念简报。

保留原文和原有结构。评审不等于重写。

## 2. 分级发现

| 级别 | 定义 |
|---|---|
| 阻塞 | 目标、核心规则、范围或证据存在矛盾，继续实现会得到错误结果 |
| 严重 | 可以继续，但很可能破坏玩家决策、实现一致性或内容生产 |
| 优化 | 不影响主闭环的表达、效率或体验改进 |

每条发现采用：

1. **位置或原文**：指向具体章节、句子、规则、参数或状态。
2. **问题**：说明哪里冲突、缺失或不可判定。
3. **影响**：会怎样改变玩家行为、实现、内容或测试。
4. **最小修改**：给可以执行的改法，不只说“补充说明”。
5. **回归面**：修改后还要检查什么。

没有具体证据时，不写“整体不够完整”“可以更丰富”“建议进一步优化”。

## 3. 修订

用户要求修改时直接改正文。先确认：

- 原设计解决什么问题。
- 什么新信息触发了变化。
- 哪个价值必须保留。
- 新方案牺牲了什么。

收到试玩、日志或新限制时，先在内部区分观察事实、实现缺陷、结构风险、样本局限和原因解释。保留构建版本、测试场景、玩家分组、样本量、分子/分母、时间窗和事件口径；缺少关键口径时收窄结论，不补造精度，也不把旧实现的问题直接归因于新设计。

多轮修订先做承接表：

| 上轮项目 | 当前证据 | 处理 | 理由 |
|---|---|---|---|
| 已验证有效改动 | 是否仍在同版本/场景成立 | 保留 / 回退 | 不因新问题无关重写 |
| 未验证设计 | 是否可能造成新问题 | 继续观察 / 修改 / 删除 | 写出根因假设 |
| 原指标 | 原名称、分子/分母、场景、时间窗 | 原样沿用 / 明确换口径 | 禁止无证据改名或迁移场景 |
| 新限制 | 影响的规则与范围 | 收缩 / 替代 / 阻塞 | 写出挤出项 |

然后建立影响清单。核心玩法变化通常检查：

- 设计首页和玩法走读。
- 瞬时、单局和长期循环。
- 输入、状态、胜负、失败和重试。
- 敌人、数值、成长和经济。
- 关卡、内容模板和难度曲线。
- UI、反馈、镜头和教学。
- 验收、测试和关键决策记录。

只更新真实受影响项，不机械勾完清单。

关键修改建立内部追踪链：

`证据 → 原规则 → 根因 → 新规则 → 参数/内容/反馈影响 → 验收信号 → 回退条件`

根因检查顺序为：目标与奖励、规则和默认行为、敌人/空间配置、上一轮教学、反馈可读性、操作窗口。不得先用箭头、警告、倒计时或文案掩盖前四层问题。若同时修改多个高影响变量，只评价组合方案；要证明单项因果，保持其余变量与基线一致。

数值变化按 [numerical-validation.md](numerical-validation.md) 重新运行公式断言、数值账本和正常/边界例；规则变化重新攻击重复触发、资源耗尽和支配策略。最终 GDD 只呈现修改后的当前规则，证据分类和原因解释只在评审报告需要时展示。

修改后同步更新 `design-contract.json`、本轮计算、测试与运行证据并重新校验，再进行一次与写作分离的语义复核；旧结果不能证明新版本通过。按 `通过 / 需迭代 / 阻塞` 给出结论。约束越界、事实口径漂移、核心路径不可达、关键数值不可复算、P0 超出明确容量或必需原型路径未实测均属于阻塞，不能仅列为一般风险。

## 4. 变更摘要

修订后用短表记录：

| 变化 | 原设计 | 新设计 | 原因/取舍 | 影响面 |
|---|---|---|---|---|

正文只保留当前真值。被否决规则进入决策记录，不在现行章节中保留“旧版可能也可以”的模糊表述。

## 5. 常见高风险评审点

- 首页承诺与实际循环不是同一个游戏。
- 循环、机制和首个可玩范围对同一条规则、次数、资源或内容量给出不同版本，却没有说明切片差异。
- 玩法走读中没有真正选择，只有执行步骤。
- 长期系统没有回流到下一局选择。
- 机制输入、状态、结算和反馈互相矛盾。
- 一个选项在所有局面都更优。
- 初始数值被写成已验证平衡。
- 关卡要求玩家使用尚未教会的规则。
- UI 或文案描述与实际状态不一致。
- 新增功能没有挤出任何范围。
- 文档大量使用通用形容词，无法指导实现。
- 用“心流、黄金比例、损失厌恶”等原则名称替代当前项目的行为证据。
- 商业、技术和项目章节很完整，核心玩法却没有具体走读、规则或首个可玩证明。
- 把计划中的功能与竞品已上线功能并列打勾，制造虚假优势。
- 市场、留存、转化、收入、价格、平台或法规陈述没有当前来源，却写成事实。
- 里程碑只有日期和功能清单，没有验证目标、退出证据和失败回退。
- 生产范围、人员排期和技术选型与团队能力、负责人确认或依赖不匹配。
