## 1. 内容生产结构

批量内容之前先定义生产规则：

- **内容单位**：一关、一房间、一波敌人、一任务节点、一张牌或一个事件。
- **固定字段**：每个单位都必须描述的信息。
- **变化轴**：空间、敌人、资源、目标、时间、信息、限制或后果。
- **组合规则**：允许、禁止、互斥、前置、权重、去重和复用。
- **曲线**：新知、练习、组合、压力、缓冲、检验和变式。
- **边界**：哪些可程序化，哪些必须人工判断，哪些需要专业资产。

先写少量覆盖常规、边界和失败情况的样例，验证模板后再扩量。用户明确要批量正文时，转交适合的生产能力；本 Skill 负责结构、样例和验收。

## 2. 关卡规格

每关围绕一个玩家问题或体验变化组织：

1. 入口状态：玩家已掌握什么、带着什么资源和能力。
2. 本关问题：这次要求玩家观察、判断或执行什么。
3. 空间与信息：动线、视线、地标、危险、安全和返回路径。
4. 阶段：准备、提问、尝试、反馈、变化、检验和缓冲。
5. 对象：敌人、机关、资源、任务、事件和可选目标。
6. 失败与恢复：软锁、死锁、越界、卡位、存档和重试。
7. 通过标准：主路径、可选路径和不同策略的验收。

空间影响判断时给节点图、草图或带图例的布局。没有真实空间关系时，不用文字声称“已完成关卡设计”。

落地前做路径可达性走查：从入口按节点逐步记录玩家位置、当前目标、已掌握规则、可用能力、资源、门槛和退出条件，至少覆盖最短主路径、一次合理失败恢复和一条可能的绕过路径。必须确认终点可达、必需能力已经教学、门锁有钥匙、放弃/死亡后能恢复，并且没有直线穿越、回不了主路或目标状态互相等待的软锁。

## 3. 首局与引导

不要套“30 秒内教学”“首步绝不失败”“完成率必须 90%”等无项目依据的通用指标。先定义这个游戏需要玩家何时理解什么。

按“目标 → 可供性 → 尝试 → 反馈 → 再应用”安排教学：

- 先给玩家一个能理解的目标。
- 在可以操作时提供信息，不提前倾倒规则。
- 用场景和反馈教学，文字只补无法从操作推断的信息。
- 新规则先单独出现，再与旧规则组合。
- 失败若是学习的一部分，要让原因可读且重试足够快。
- 教学完成不等于学会；安排一次无提示再应用。

试玩显示玩家没有迁移所学行为时，先检查教学是否教会了与正式目标相反的策略、正式任务是否奖励错误行为，以及敌人和空间是否让主目标与战斗目标竞争；不能直接把提示完成率当成实战掌握率。只有规则、目标和空间关系正确后，才逐步淡出提示并测试无提示应用。

引导步骤规格：

| 字段 | 内容 |
|---|---|
| 入口状态 | 玩家知识、能力、资源和当前目标 |
| 触发 | 位置、事件、时间或状态条件 |
| 允许输入 | 此刻可以做什么、暂时限制什么 |
| 系统响应 | 正确、错误和中断输入怎样处理 |
| 信息 | 场景、UI、镜头、音频或文本承担什么职责 |
| 通过 | 玩家用什么行为证明理解 |
| 恢复 | 跳过、失败、退出和再次进入 |
| 观察 | 困惑、误读、迟疑和自主应用信号 |

## 4. 叙事和文案需求

GDD 只写与玩法相关的叙事结构和文案需求：

- 核心矛盾如何进入玩家选择和系统后果。
- 角色知道什么、想要什么、用什么策略。
- 哪些状态改变对白、任务和世界。
- UI、任务、引导和错误文本出现在哪里、解决什么信息问题。
- 术语、变量、长度和分支约束。

用户要求大量对白、UI 文本或剧情正文时，把场景、触发、角色关系、术语和验收交给游戏内容写作能力，不让 GDD Skill 同时承担整套写作生产。

## 5. 验收

- 内容单位字段完整且能复用。
- 变化轴真的改变玩家判断，不只是换皮。
- 难度来自组合和压力，不只来自数值膨胀。
- 关卡入口状态与玩家已学知识一致。
- 引导文本描述的是当前可执行动作。
- 失败原因可读，恢复路径可用。
- 状态、任务、UI、文案和测试使用同一术语与真值。
- 节点图、文字路线、触发条件和玩家能力表能走出同一条可完成路径。
- 新增空间、敌人、脚本、资产和反馈均在当前内容与制作预算内，并有对应回退项。
