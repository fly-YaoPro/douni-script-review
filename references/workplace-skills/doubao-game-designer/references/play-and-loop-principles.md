## 1. 把循环写成因果链

核心循环不是功能清单，也不只是闭合箭头。至少说明：

`局面/需求 → 玩家读取信息 → 采取行动 → 系统状态变化 → 玩家感知反馈 → 形成理解 → 出现新压力、机会或目标 → 再行动/转向/停止`

检查六个问题：

- 玩家具体做什么，而不是系统自动做什么。
- 玩家依据什么信息选择。
- 行动改变了哪个可持续状态。
- 玩家怎样知道结果和原因。
- 结果为什么不是终点，而会改变下一次决定。
- 什么时候循环结束、升级、分叉或进入另一层。

动词必须带来判断。“移动、点击、收集”只是输入；“绕到无掩体一侧换取更快清理”才是玩法关系。

## 2. 找到真正的核心

把“80/20”当成注意力检查，不当成固定比例：

- 玩家最常重复、最能区分本作的行为是什么。
- 去掉成长、奖励、叙事包装和内容数量后，它是否仍产生选择与反馈。
- 哪些功能只服务少数场景，却吞掉大量制作成本。
- 哪个最小组合必须先成立，其他系统才值得制作。

约束不是“快、便宜、好只能选二”的口号。写出当前真正不可同时满足的目标、选择保留什么、牺牲什么，以及改变决定需要什么新证据。

核心循环未成立时，先重组现有规则、目标、敌人/空间配置和奖励，不扩展角色、技能、资源、成长与内容数量。每条新增规则都说明：解决的问题、生命周期、默认行为、失败模式，以及为什么不能复用当前结构；回答不了就不进入 P0。

## 3. 设计有意义的选择

一次选择至少需要：

| 要素 | 问题 |
|---|---|
| 信息 | 玩家在决定前知道什么，哪些不确定性可推断 |
| 选项 | 至少两个行为是否都真实可执行 |
| 取舍 | 得到什么，同时放弃或承担什么 |
| 后果 | 结果是否改变后续状态，而非只换一段演出 |
| 反馈 | 玩家能否把结果归因到自己的判断 |
| 再选择 | 后果是否产生新的应对，而非立即回到原状 |

检查支配策略、无意义选项、答案提前显露、随机性淹没判断、代价不可读，以及失败后只能等待的问题。不要为了“策略性”机械制造三条路线。

## 4. 检查系统协同与主题

题材是“发生在哪里、长什么样”；主题是游戏反复通过规则和后果表达的判断。主题不必先写成文学命题，但不能只靠美术和对白存在。

用短表检查：

| 支柱/主题判断 | 核心机制如何表达 | 内容怎样制造变式 | 反馈怎样让玩家读到 | 反例/禁止项 |
|---|---|---|---|---|

系统交互至少抽查：

- A 与 B 叠加是否产生新的玩家选择。
- 交互是预期、可接受涌现，还是破坏规则。
- 某系统是否只增加步骤，没有改变判断。
- 一个模块失效时，主循环是否仍成立。

复杂项目可用交互矩阵记录“增强、抑制、依赖、冲突、无关系”，只展开真实存在的交互。

## 5. 组织难度与节奏

不要套固定“每七分钟一个新元素”或统一注意力时长。按玩家能力与当前任务安排：

`建立目标 → 单独认识规则 → 低压尝试 → 无提示再应用 → 与旧规则组合 → 在压力下检验 → 缓冲/重构`

难度可来自信息不足、执行窗口、资源、空间、组合、不可逆性、时间或对手适应。先指出是哪一种，再调对应杠杆。

如果使用动态难度，写清：

- 观察什么行为，为什么能代表困难。
- 改变什么，不改变什么。
- 是否需要向玩家公开、允许选择或提供固定模式。
- 如何避免惩罚熟练表现、破坏规则一致性或让胜负失去可信度。

“玩家察觉不到”不是目标；公平、可解释和不背叛既有规则才是边界。

## 6. 区分错误并设计恢复

先判断失败来自哪里：

| 类型 | 典型原因 | 优先检查 |
|---|---|---|
| 感知 | 没看见危险、目标或状态变化 | 信息层级、预告、遮挡、反馈 |
| 理解 | 误解规则、因果或目标 | 教学顺序、术语、例外、一致性 |
| 执行 | 输入、时机、瞄准或动作窗口失误 | 可供性、缓冲、窗口、控制 |
| 计划 | 信息已知但策略判断失败 | 取舍是否真实、后果是否可预期 |
| 遗漏 | 忘记步骤、资源或约束 | 记忆负担、状态外显、提醒 |
| 系统 | 卡位、软锁、网络或实现错误 | 规则边界、恢复、技术修复 |

不要一律降低难度。感知错误先修可读性，理解错误先修规则表达，执行错误再考虑窗口，计划错误可以保留但要让复盘成立。失败应说明原因、保留适当后果，并给与学习目标相符的恢复路径。

出现“玩家没有按设计行动”时，不默认归类为遗漏或感知问题。依次检查任务目标、收益、风险、默认行为、敌人/空间压力和前序教学是否在奖励相反行为；只有底层关系成立后，才用箭头、倒计时、警告或文案降低剩余信息成本。

## 7. 用极端值探测参数

原型期可临时把关键参数调为约 `0.5×` 或 `2×`，观察行为是否显著变化。这是敏感性探针，不是平衡结论。

记录：

| 参数变化 | 预期行为 | 实际行为 | 新的支配策略/死区 | 下一步 |
|---|---|---|---|---|

若极端变化仍不改变玩家决策，参数可能不是有效杠杆；若直接破坏循环，说明需要缩小合法范围或重做关系。正式初值仍需正常例、边界例和真人体验校准。

## 8. 让原型回答问题

按问题选最低成本原型：

- 纸面/表格：资源流、卡牌、概率、路线、回合与内容组合。
- 灰盒数字原型：输入手感、时间窗口、空间、物理、镜头和多人同步。
- 交互线框：导航、信息层级、操作顺序和错误恢复。
- 内容样例：关卡模板、谜题、事件、敌人组合是否可生产。

每轮写清：验证目标、任务、观察对象、成功/失败阈值、适用版本，以及两种结果分别触发的修改规则。分开记录“发生了什么”和“为什么发生”；玩家说难不等于只需降难，设计师认为玩家没理解也不等于玩家有错。

需要判断某项改动是否有效时，冻结版本、任务、敌人/关卡配置和统计口径，一次只改变一个高影响变量并保留基线。多变量方案可以验证整体是否改善，但不能把结果归因于其中一项。下一轮先保留已验证有效的变化，再重新检查上一轮未验证的设计是否可能造成新问题。

## 9. 原则不是证据

心流、Fitts、Hick、损失厌恶、锚定效应或任何命名原则只能帮助提出问题，不能直接证明方案正确。

- 不把通用数字、时间或选项数量当行业真值。
- 不用原则名称替代当前项目的行为证据。
- 参考作品只证明某方案曾在特定上下文成立。
- 体验结论只在证据支持时写入；验证前只写测试目标、调节杠杆、阈值和对应处理规则。
- 若原则与真实试玩或可访问性需求冲突，以当前证据和项目目标重新判断。
