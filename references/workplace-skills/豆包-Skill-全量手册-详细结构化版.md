# 豆包 Skill 全量手册（深度结构化版）

> 本手册覆盖豆包**内置的全部 108 个 Skill**，按八大领域组织。每个 Skill 统一按"深度十段"拆解，目标是**不打开 SKILL.md 也能判断：该不该用、有哪些工具/子能力、按什么流程跑、要什么输入、交什么产物、不能碰什么、内部有哪些资产可复用**：
>
> 1. **一句话定位**：本质是什么
> 2. **核心能力**：子功能 / 子技能 / 能力分支
> 3. **工具与命令**：CLI 命令、工具函数、子技能逐个列（无 CLI 的 Skill 省略本段）
> 4. **工作流程**：步骤、决策门、状态机、分级
> 5. **触发场景**：什么需求进来（含典型触发词）
> 6. **不适用与边界**：什么不该用、`→ 转交` 哪个姊妹 Skill
> 7. **输入要求**：启动必备材料与关键参数
> 8. **交付产物**：最终形态（对话 / 飞书文档 / Word / Excel / 媒体 / 应用 / 代码）
> 9. **关键约束与风险**：硬规则、错误码、风险分级
> 10. **内部资产**：references / scripts / sub-skills / branches 分组清单与规模
>
> **阅读提示**
> 1. 路由先看「触发场景 + 不适用与边界」两段；姊妹路由用 `→ 转交 xxx` 标注。
> 2. 「工具与命令」段是可直接照抄的能力清单；命令参数以实时 `--help/--schema` 为准。
> 3. 「内部资产」告诉你这个 Skill 还藏了哪些可深读的参考文件、可直接跑的脚本。
> 4. 本手册只做能力导航，不替代各 SKILL.md；Skill 更新后以实时文件为准。

# 一、学术科研与医学（14 个）

### 1.1 学术文献调研（`doubao-academic-researcher`）

**一句话定位**：在未锁定具体论文前，系统摸清一个学术方向的研究现状、热点前沿、学术史与选题依据，产出结论先行、引用可追溯的结构化综述。

**核心能力（4 个子技能管线）**
- **literature-scout 文献检索核验**：多视角检索式、引用真实性五级核验（VERIFIED / MINOR / MAJOR / UNVERIFIABLE / PAYWALL）、灰区文献一律剔除
- **research-synthesis 证据综合**：双轴证据分级（研究设计层级 × 学科适配度）、主题聚类、文献矩阵、争议与空白、自对抗审查
- **review-writing 综述成稿**：claim/citation/tension/gap 四类素材池，出文献地图、逻辑图、主题章节、完整综述稿
- **document-delivery 文档交付**：默认生成飞书云文档并回读自检

**工作流程**：冻结研究简报 → 检索+逐条验真 → 双轴分级与聚类 → 自对抗 → 双层成稿（调研结果层 + 综述参考稿层）→ 飞书文档回读。

**触发场景**："调研某方向""梳理 related work / 研究现状""看最新进展/学术史""找文献支撑观点""选题依据"。

**不适用与边界**：不出 IMRaD 成品、不代写论文章节 → `doubao-academic-polish`；评判想法 → `doubao-academic-evaluator`；逐篇精读 → `doubao-paper-close-reading`；只查引用真假 → `doubao-reference-audit`。

**输入要求**：研究主题/问题、学科、时间窗、输出语言、证据标准（开工先冻结研究简报）。

**交付产物**：默认飞书云文档 + 对话摘要，含文献地图表、核心逻辑图、参考文献清单。

**关键约束**：①不可核验引用一条不进，DOI 能解析但标题不符按幻觉拦截；②证据分级尊重人文/质性范式，不搞"非 RCT 即低质"；③IRON RULES 高于临时指令。

**内部资产**：4 子技能；references 3 篇（evidence-hierarchy 证据层级、hedge-calibration 措辞校准、output-structure）；scripts 5 个（workflow 主流程、validate_run 门禁、check_lark_doc/check_review_draft 回读、research_visuals 图表）；scout 下另含 citation-protocol、search-strategy，synthesis 下含 quality-gates/self-adversarial 等。

### 1.2 论文写作润色（`doubao-academic-polish`）

**一句话定位**：学术论文正文写作、结构设计与语言润色总入口，按"产物类型 + 语言"分流到三条工作线。

**核心能力（三条工作线）**
- **paper-write-zh 中文撰写**：evidence-driven-writing（证据驱动）、stem（理工）/hss（人文社科）两套范式、literature-search/literature-review/writing-chapters/writing-core 模块
- **paper-write-en 英文撰写**：prepare 阶段用 verify_literature 联网验真；含 APA7/MLA9/Chicago18 三套格式指南、table-figure 图表规范、7 个章节 subskill（方法/结果讨论/结论/文献综述/理论框架/整合审校/格式）
- **paper-shape 结构/润色**：结构模式只组织论证不代写；润色模式忠实润色/中译英、不新增研究内容；revision_guard 防越界改写

**工作流程**：判定任务类型（完整写/结构/润色/中译英，任务类型优先于语言）→ 选工作线 → prepare 验真 → 成稿 → check_draft/check_prepare/check_lark 校验。

**触发场景**："帮我写论文/这一节""扩写成章节""中文材料写成英文""润色但不改意思""只给结构提纲""学术中译英"。

**不适用与边界**：先评研究是否成立 → 先转 evaluator；先系统调研 → 先转 researcher；会改变科学含义的改动必须标出请作者确认。

**输入要求**：已有材料/数据/想法、目标语言、任务类型、目标期刊要求（可选）。

**交付产物**：成品正文（文档/在线文档），只出成品，不带内部检查痕迹。

**关键约束**：①忠于原意绝不虚构数据/文献/机制；②输出干净，不打印 handoff/流程；③发现深层硬伤转 evaluator 不糊过。

**内部资产**：3 工作线（zh/en/shape）；en 线 8 subskill + 3 格式指南 + 5 scripts（check_draft/check_lark/check_prepare/status/verify_literature）；zh 线 stem/hss/literature-search/literature-review/writing-chapters/writing-core 模块；shape 线 revision_guard.py + polish/structure 两篇。

### 1.3 学术评审诊断（`doubao-academic-evaluator`）

**一句话定位**：以资深审稿人/导师视角做"只看不改"的诊断——评判想法值不值得做，或给成稿挑硬伤、判断能不能投。

**核心能力（2 个子技能）**
- **idea-evaluate 想法评估**：复述 → 致命伤检查 → 处境匹配 → 五维打分（更准/更快/更稳/更省/更广，默认 5 分起评）→ 颠覆性判断 → 可行性；结论 Strong Accept / Accept with Revisions / Reject and Pivot
- **submission-review 成稿审查（六层）**：①逻辑链 ②主张-证据匹配 ③新颖性 ④写作 ⑤AI 腔 ⑥图表；问题分 **CRITICAL（足以拒稿）/ MAJOR（一审必点）/ MINOR（打磨级）**；重点查核心结果归因是否干净、"comprehensive/第一个"过度声明、失败案例与局限；按学科切换范式（STEM 看基线/消融/可复现，社科看操作化/样本/统计，经济看识别策略/robustness）

**触发场景**："帮我看看这个想法""值不值得做""投稿前审一遍""能不能投""这批实验数据撑不撑得住观点"。

**不适用与边界**：只诊断不代写（不重写正文/不画图/不重跑数据）→ 写作转 polish；没有的数字绝不编；只有想法走 idea-evaluate，已有草稿走 submission-review。

**输入要求**：想法（假设+机制+方案）或论文草稿；实验数据与对应主张；学科与目标期刊/会议。

**交付产物**：简短判断直接对话；完整审查先出 Markdown 源稿再转飞书文档（无权限则保留 Markdown）。

**关键约束**：①没给的数字绝不编（最高优先级）；②判断指向原文具体位置，不空泛；③未验证想法最多"值得一试但需实验确认"；全程引用文献 ≤15 篇。

**内部资产**：2 子技能；references 5 篇（fatal-flaws 致命伤清单、five-dimensions 五维锚点、domain-evaluation-frameworks 分学科框架、section-guides 分节指南、forbidden-patterns 禁 pattern）。

### 1.4 论文深度精读（`doubao-paper-close-reading`）

**一句话定位**：对一篇或少量论文做专业深度精读，讲清问题、故事、方法机制、关键证据、结果、可信边界、复现风险与启示。

**核心能力（七阶段）**：确认材料与目的 → 建论文全景 → 重建故事与论证链 → 拆方法/理论/机制 → 深读证据实验与异常 → 形成批判与可信边界 → 转化研究价值。内置专家经验：贡献声明≠贡献证据、图表往往比正文诚实、消融≠自动因果、强结果要看比较是否公平、局限≠否定论文。可追加方法/公式专项、复现清单、少量论文对比、组会汇报提纲、后续阅读路线。

**触发场景**："论文精读/深度解读""分析方法与实验""判价值或局限""值不值得引用/复现""组会精读笔记"。

**不适用与边界**：无种子论文的开放综述 → researcher；只核验 DOI/文献真假 → reference-audit；代写/润色/排版 → polish / journal-format；只有摘要节选不得冒充全文精读。

**输入要求**：PDF/Word/MD/正文/arXiv/DOI/标题；阅读目的（理解贡献/学方法/判可信/备复现/做比较/找启发）；图表、参考文献、补充材料。

**交付产物**：完整 Markdown 精读报告 + 内容一致并回读的飞书文档；飞书不可用时 Markdown 即完整交付（模板见 assets/report-template.md）。

**关键约束**：先理解再评价、先给判断再展开；全文看见但重点深读；深度服从用户目的，不对外包装成"低中高档产品"。

**内部资产**：assets/report-template.md 报告模板 1 份。

### 1.5 研究计划书撰写（`doubao-research-proposal`）

**一句话定位**：面向基金申请、开题报告、人才计划的学术提案撰写、审查与优化。

**核心能力**：国自然（面上/青年，附 2026 指令与大纲模板）、国社科、博士后/人才计划、学位论文开题、保研申博访学联培；基于已有成果形成立项书、区分"事实"与"AI 建议"、任务书一致性检查、补强论证逻辑、分阶段确认、信息分层。

**工作流程**：定申请类型 → 套对应模板/指令 → 研究逻辑设计 → 文献综述（防编造）→ 分检查点确认 → 输出与校验。

**触发场景**："写基金申请/国自然""优化开题报告""审查研究计划""按已有成果写立项书""核对模板"。

**不适用与边界**：全面文献计量综述 → researcher；从零选题/纯润色 → evaluator/polish；法律医疗财务高风险结论不在范围。

**输入要求**：研究方向与已有成果、申请类型、模板/格式要求、研究基础与团队。

**交付产物**：研究计划书/立项书（事实与 AI 建议分层标注）。

**关键约束**：严格区分已有事实与 AI 补充；任务书各部分逻辑一致；参考按需加载；反编造规则。

**内部资产**：references 7 篇（grant-guide、scenarios-guide、anti-fabrication-rules、literature-review-guide、research-logic-design、workflow-checkpoints、output-and-validation）；assets/templates 6 份国自然/国社科 .doc/.docx 模板。

### 1.6 参考文献审查（`doubao-reference-audit`）

**一句话定位**：系统审查参考文献真实性、题录准确性、文内—文后对应，以及正文主张是否真被引用文献支持。

**核心能力（七阶段）**：理解论文与审计目标 → 建全量引用地图 → 核验文献身份与当前状态（Crossref 题录查询器）→ 判引用角色与风险 → 按风险升级证据 → 主张—证据实质比较 → 归并出报告。识别错引、过度推断、二手转引、主题相关但不支持、组合引用、强措辞弱证据、把自己结果甩给被引文献证明等问题。

**触发场景**："论文/参考文献审计""引用核对""引用是否支持观点""查错引/过度推断/二手转引"。

**不适用与边界**：开放综述 → researcher；整篇精读 → close-reading；代写/润色 → polish。

**输入要求**：论文全文 + 参考文献清单（最好含正文引用位置）；目标期刊引用格式（可选）。

**交付产物**：专业引用审计报告（结论、核心发现、修改建议、实质性引用问题、题录版本问题、结构观察、证据边界）+ 飞书文档。

## 附录 D：使用与维护说明

**Skill 位置**：本手册仅收录豆包内置 Skill，位于内置库 `.skills` 目录，共 108 个，分八大领域（14+12+12+13+6+21+9+21=108）。

**调用纪律**
- Skill 名不是可调用函数；CLI 类（mediakit-cli、lark-cli）先 `--help/--schema` 取实时机器合同，参数以实时输出为准。
- 飞书写操作先 `--dry-run` 再 `--yes`；MediaKit 异步任务用 task_id + `shared query-task` 轮询（单次最长 9 分钟，到点 exit 0 且 running 属正常，用同一 task_id 续查）。
- 涉及 MCP 工具（如 Linkly）先 tool_search 取真实 schema，不凭工具名猜参数。
- 使用任何 Skill 的命令/脚本前先 Read 其 SKILL.md，不凭描述直接运行。

**维护本手册**
- Skill 新增/升级/改名后，按"扫描内置 `.skills` 目录 → 对齐八大领域 → 更新计数与目录 → 文档条目与目录名逐一比对"的流程刷新；编号条目数必须与内置目录数一致。
- 本手册为能力导航，参数与枚举以各 Skill 实时 SKILL.md / `--schema` 为最终依据；轻量与编排型 Skill 可能随版本合并或扩充。
