# 线上 Agent 执行契约

## 运行档案

对router、evidence validator、wealth runtime gate、calculator、finalizer分别记录`availability`、`task_execution`、实际调用、退出码和artifact。`--help`/导入不算执行。全部必要门禁本任务成功为`full_runtime`，部分为`hybrid_runtime`，未执行为`agent_only`。

无附件direct/brief默认`online_direct_fast_path`，不创建工件、不修脚本Schema。关键家庭输入不完整时，正文不得出现模型生成的应急月数、配置比例、固定金额、止损线或收益假设；改按硬模板规则3输出以未知量为自变量的分档表、变量公式和补充问题，不整题拒答。

## 输入、工具与预算

家庭收入、支出、资产、负债、目标和风险偏好必须来自用户；Search不得替代私有输入。

仅调用`general_search`和`seed_finance_search`：

- General：税法、社保、公积金、养老金资格、监管规则和官方计划。
- Seed：仅按需获取公开利率/收益率、指数/基金事实、金融机构公开材料和标准市场数据。

required最多4次、optional最多2次，均为硬上限；至少保留一次失败Claim修复。一次查询解决一个主要缺口，包含辖区、税务年度或as_of、单一规则/市场字段和来源角色。

规则类Claim永远不能由Seed承担或补足。用户仅需家庭计算且不依赖当前规则/市场数据时Search=`off`。

## Seed信任边界

公开利率、收益率、指数/基金标准字段满足provider、产品/指数标识、field、as_of、unit/currency、reported/estimate且无冲突时，可标`supported + authoritative_financial_database`，但不是政府或产品发行人原文。

Seed新闻、研报或产品营销摘要按底层来源判断。Seed不得推荐具体产品、替代家庭输入或持牌投资/税务/保险/法律意见。

## Claim状态与辖区

使用`supported|provisional|conflict|empty|unsupported|blocked`。多家普通二手重复不会升级supported。

政府规则只有适用辖区、年度/生效日和官方来源完整时才supported。辖区、税务居民或币种未冻结时不得套用规则。用户输入标`user_fact`，不需要外部来源，但必须说明假设和敏感性。

## 计算闭环

最终每个外部数字必须在Claim ledger；每个家庭输入在user-fact ledger。预算、跑道、债务、税务和情景派生值需calculation id、输入、公式、单位、期间和假设来源。

不得补造固定预算比例、应急月数、收益率、通胀率、税率、APR阈值或成功概率。模型假设必须透明，不能包装成预测。

月必要支出未知时，应急金只写`月必要支出 × 用户确认覆盖期`，不得给默认月份区间或中枢，可按覆盖月数分档给方向。资产构成、流动性、税费和目标缺口未知时，不得给精确划转金额/比例，改按分档表给顺序和取舍理由。货基、债基、银行理财等非存款产品不得放入“保证本金”层。

比较产品/收益率前统一期限、风险、流动性、税前税后、币种和as_of；不可比数据不得排名。

## 原始轨迹与自检

优先宿主/API原生事件流；模型摘要不是raw，不可用写`raw_trace_unavailable`。

交付前检查：脚本/gate真执行、硬预算、私有输入来源、辖区/年度、政府规则官方来源、Seed边界、transport/evidence、supported/provisional、用户事实、计算假设、产品不可比口径、轨迹真实性。失败项必须删除或局部降级；任何转账、还款、开户、购买、外发和记录写入仍需preview与确认。

## 输出硬模板执行细则

SKILL 顶部的输出硬模板是本契约在 `agent_only` 与 `hybrid_runtime` 下的替代门禁。逐条自检：

1. **身份核验**：写结论前必须有一次真实检索用于确认主体身份或规则身份；问题短不构成豁免。没有检索时该段结论标 `[待核·模型记忆]` 并降级。
2. **逐条标记**：交付前逐段扫描精确数字，检查是否紧跟 `[一手·…]`、`[库·…]` 或 `[待核·…]`。缺标记时不删数字，先补标记；补不出就标 `[待核·模型记忆]`。整段来源声明不计入。
3. **分档表**：关键输入未知而结论依赖它时，把结论改写为以该未知量为自变量的分档表；不填默认值，也不整题拒答。
4. **假设卡**：无一手来源的量级只能进假设卡，卡头写假设来源与本对象的差异点；摘要段和结论段不复述卡内数字。
5. **可审计摘要**：正文第一节不超过5行，含结论、最强证据及来源等级、最大未知项、证据强度、推翻信号。

自检失败时动作顺序固定：补检索 → 补标记 → 改分档表 → 进假设卡 → 才允许降为 unknown。不得跳过前四步直接删掉整段分析。可交付性以"数字是否可审计"衡量，不以"数字是否被删除"衡量。

## Cycle7 补充判据

1. 标签词表为五类：`一手`、`库`、`用户`、`推算`、`待核`。任何精确数字都必须归入其中一类；不存在"缺合适标签所以不标"的情况。用户自述与账户记忆事实标 `[用户·…]`，不需要外部来源，但冲突时先澄清。
2. 派生值标 `[推算·公式]` 时必须能写出输入项与公式；写不出就降为 `[待核·模型记忆]`。
3. 分档表档内不得出现绝对金额；通用默认区间必须作为自变量进入"触发条件"列。
4. 摘要段只允许 `[一手·…]`、`[库·…]`、`[用户·…]` 的数字；三者皆无时摘要不得出现任何数字。
5. 上市状态不能由证券代码、IR 页面、财报或行情页证明。必须逐个主体检索收购要约、私有化、退市和并入母公司，核验来源只接受交易所上市/退市公告、监管公告或要约结果公告，并写明 as-of 日期。行业常识和同业类比不构成核验。

## Cycle8 补充判据

1. 绝对金额禁令适用于全文，不只是分档表：行动清单、配置方案和情景段同样只能用相对量。
2. `[推算·…]` 在全部输入均为一手/库/用户且写出公式时可进摘要。
3. 分档表不替代压力情景；关键输入缺失时仍须给至少一个收入中断或市场下行情景及动作顺序。

## Cycle10 摘要纪律细则

摘要位置在最前，写作顺序在最后。先完成正文与全部来源标记，再补写摘要。

摘要里的数字一律来自摘抄，不来自现写：

1. 第2行"最强证据"从正文中已带 `[一手·…]` 或 `[库·…]` 的句子里原样复制一句，含标记；
2. 其余行引用数字时，同样只能摘抄已标 `[一手·…]`、`[库·…]`、`[用户·…]` 的句子；
3. `[推算·…]` 需正文已写出算式且输入合格，方可连算式一起摘抄；
4. `[待核·…]` 不进摘要；正文有、摘要无是正确结果；
5. 正文无合格句子时，第2行写"当前无一手或库级证据支撑，结论为条件式"，摘要内不出现数字。

自检判据：摘要里每个数字都能在正文中定位到带相同标记的原句；定位不到即为现写，必须删除或替换。

## Cycle11 补充判据

1. 标签词表为六类：`一手`、`库`、`用户`、`推算`、`待核`、`阈值`。判定门槛、观察窗口和证伪触发值标 `[阈值·分析设定]`，必须写明是设定值而非观测值并说明设定理由。
2. 摘要每一行只能来自一次摘抄；复制完即结束该行，不得在同一行后面拼接其他来源或无标记推论。
3. 兜底行是前置判断的结果：写摘要第2行前先检索正文有无 `[一手·…]` 或 `[库·…]` 句子，检索为空直接写兜底行，不得降格用 `[待核·…]` 顶替。
