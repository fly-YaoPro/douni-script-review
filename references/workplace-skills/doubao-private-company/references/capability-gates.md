# 分层能力门禁与部分回答协议

## 1. 先拆结论槽位

每次独立判断：mandate fit、商业/技术质量、估值方法、交易可行性、回报可计算性、下一动作。一个槽位缺输入，不得暂停其他可答槽位。

## 2. 分层 gate

### `can_form_research_view`

对象、产品和 as-of 可识别，且公开信息或通用机制足以回答商业方向、技术路线、产业结构、估值方法或会议价值时为 true。允许输出“已知事实 + 关键未知 + 若/则关系 + 证伪信号”，不要求 mandate 或交易条款完整。

对象、法人、产品或权益边界无法冻结时，只暂停依赖该边界的强结论；仍交付可确认的最小事实和补证路径。

### `can_recommend_management_meeting`

初会是信息收集动作，不是投资批准。满足以下条件即可建议证伪型初会：

- 对象真实可识别；
- 与已知 mandate 无明确 Hard Pass；mandate 未完整时可给条件匹配；
- 存在能显著改变下一动作、且主要依赖管理层解释或非公开信息的 kill questions；
- 预期信息价值高于会议成本。

不得要求会前已取得审计财报、客户合同、完整 cohort 或 Term Sheet。下列情况才降级或不建议初会：对象不明；已确认 Hard Pass；无真实接触窗口且用户只问具体交易；公开事实已构成不可逆 Hard Pass；对方拒绝最基本的主体、融资窗口或数据真实性声明。

### `can_recommend_data_room_access`

数据室是信息获取层，不是投资推进。初会已完成，公开证据方向积极且可交叉验证，并且定向数据请求能显著改变商业、技术或风险判断时，可建议“条件进入数据室”。请求必须对应具体未知和升级/降级条件，不能用材料数量作门槛。

该 gate 为 true 不推出 mandate fit、交易可行、估值可接受或可进入 IC；这些仍由投资推进和回报门禁独立判断。若公开证据为负、对象边界仍不清、初会无法解释核心矛盾，或对方拒绝最基本真实性核验，则不建议进入数据室。

### `can_recommend_investment_progression`

条款评估或投资推进需要相应阶段的 mandate、可投额度、工具、权益、估值口径、关键商业数据和退出框架。缺失时交易可行性保持 unknown，不得给推进投资、接受估值区间或精确回报。获得数据室访问权本身不满足任何交易门禁。

`IC` 只能作为后续节点，本 Skill 不作批准。

## 3. 估值协议

固定顺序：

1. 冻结对象：独立公司、母公司业务、合资主体或某轮证券；
2. 冻结权益：EV、股权价值、投前/投后、普通股/优先股；
3. 冻结指标：收入、ARR、run-rate、GMV、订单和合同额不得混用；
4. 校准增长、毛利、留存、客户集中、算力/履约成本和现金消耗；
5. 选择可比、SOTP、里程碑风险调整或退出价值反推；
6. 缺输入时只给关系式：
   - `允许进入估值 = 可验证退出权益价值 ÷ 目标 MOIC − 后续稀释与优先权调整`
   - `隐含倍数 = 投后企业价值 ÷ 同口径经常性收入`

阈值只能来自基金要求、同日同口径可比、历史交易或用户确认假设。禁止默认倍数、默认概率、固定期限和“满足 N 项”的机械门槛。

## 4. 技术/产品 taxonomy、证据与价值捕获

分析技术证据前先冻结 taxonomy：

- 目标产品与目标法人业务边界；
- 传感模态；
- 刺激、解码或其他核心机制；
- 医疗、消费或混合定位；
- 硬件、软件或软硬一体交付层。

每条技术或商业化证据都必须回绑相同 taxonomy。关联方、相邻模态、不同医疗/消费定位或不同软硬件层的产品，只能作为机制或市场线索，不能证明目标技术已商业化。

技术证据依次为：性能演示 → 独立验证 → 可制造/可部署 → 系统集成 → 客户采用 → 付费与续约 → 单位经济 → 规模化资本需求。前一层不得自动证明后一层。

价值分析分别回答：

- 最终用户获得什么价值；
- 产业链创造多少总价值；
- 目标公司凭合同、IP、数据和议价权能捕获多少价值。

产业价值成立，不自动推出目标公司的股权价值成立。

## 5. Kill questions

最多 5 个，分别覆盖且不得重复：主体/技术、收入回款、临床增量、单位经济、交易。类别内部再按以下信息价值排序：能否判定 Hard Pass；是否改变下一动作；能否解释多个未知；是否只有管理层/数据室能回答；获取成本是否合理。

每个问题必须包含：

- 为什么重要；
- 什么答案会升级；
- 什么答案会降级。

不得用平铺材料清单替代问题优先级。
