# 一级投资项目评估 分析框架

## 核心分析

- Mandate fit：行业、阶段、票面、地区、持股、治理和退出期限。
- Business quality：市场、竞争、商业模式、单位经济和增长质量。
- Team quality：创始人匹配、关键人依赖、治理和历史执行。
- Deal quality：估值、条款、资本需求、稀释、保护和退出。
- Evidence quality：事实、管理层陈述、假设和待核验问题分层。
- Capability：研究观点、信息收集型初会、数据室信息获取和投资推进分别判定；局部缺口不扩张为整体拒答。

## 估值与技术纪律

- 估值顺序：对象与权益边界 → 指标口径 → 质量校准 → 方法 → 变量关系式。收入、ARR、run-rate、GMV、订单和合同额不得混用。
- 技术先做 taxonomy：传感模态、刺激/解码、医疗/消费、硬件/软件、目标产品和法人边界。再按性能演示 → 独立验证 → 可制造/可部署 → 系统集成 → 客户采用 → 付费续约 → 单位经济 → 规模化资本需求；相邻产品证据不得跨对象归属。
- 价值归属分别分析最终用户价值、产业链总价值和目标公司可捕获价值。
- 最多五个 kill questions，分别覆盖主体/技术、收入回款、临床增量、单位经济和交易，每个附升级/降级条件。

## 解释深度

1. 定位：发生了什么、哪个指标或条件变化。
2. 归因：什么业务活动、市场变量或事件驱动。
3. 约束：为什么主体不能轻易消解，或为什么机会可能持续。
4. 前瞻：结构性还是暂时性，什么信号会验证或证伪。

核心论点至少达到第 3 层；证据不足时明确降档。

## 竞争性假设

每个重要现象至少考虑两个解释，并写出区分证据。无法区分时不得选择最顺手的故事作为确定结论。

## 结论分档

- 已核验：一手来源直接支持主要链条。
- 多源支持：多个独立来源方向一致，但仍有缺口。
- 分析推断：机制合理但缺直接验证。
- 情景/假设：用于压力测试，不是事实。

## 信息增量

成稿前回答：读者相比原始材料多知道了什么？如果只有数字复述、格式整理或常识，退回分析计划。
