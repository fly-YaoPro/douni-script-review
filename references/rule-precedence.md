# 规则优先级

同一问题发生冲突时，按以下顺序处理：

1. Blackwall 权限与系统规则。
2. 当前任务开始时已生效的 `script_review:*` 审稿记忆碎片。
3. 最新会议里由客户或内部负责人明确确认的口径。
4. 当前专项 Brief。
5. 《工作任务模式提报审核必看——对机构版》。
6. 脚本正文中可核验的事实。

已确认覆盖关系：

- 后续素材统一使用“豆包工作”；不再使用“豆包专业版”。已拍好的视频暂不要求返工。
- “课程教学”是当前专项名；“科普/科普号/科普专项”历史口径归一为课程教学。
- 抖音允许出现和口播“豆包”；小红书避免口播与画面露出“豆包”，统一使用“AI”。机构版文档中与此冲突的旧句作废。
- “抖音允许出现豆包”不是“抖音每篇都必须露出豆包”。除非当前碎片、最新会议或客户明确要求，否则不得因全程使用“AI”判稿件不通过。
- 审核完整脚本，不审核纯大纲。

无法判断某条碎片是否适用时，不要静默选择；把冲突写进待确认项，暂停该项评论。

同一层级、尤其同一份 Brief 内部前后冲突时，不允许挑更严格的一句自动判错。先查更高优先级的当前碎片或最新会议是否明确覆盖；没有覆盖就不落达人批注，必要时进入内部待确认。

拍摄形式（真人、虚拟人、录屏、口播）默认属于制作方案，不是自动硬规则。只有当前生效碎片、最新会议或客户明确说“必须/统一要求”时，才能作为必须修改项。
